## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) captioned three drawn scenes and reported a `not-measurable` evaluation because no reference captions existed. This notebook keeps those scenes and their inference contract as Section 5 and adds the adaptation contract around it: a real out-of-distribution captioning corpus read column-only with per-photograph pins from one parquet row group, corpus-level captioning metrics in the carried `metrics.py` (BLEU-4, ROUGE-L, CIDEr-D), two non-neural baselines, a bounded fine-tuning of the caption decoder with the vision features cached, a per-category breakdown, the scenes re-captioned after adaptation, and an artifact that reloads. The per-image `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `pytorch_model.bin`), at the pinned revision; `verify_snapshot` re-hashes every entry — the pickle checkpoint included — before `torch` is imported; `BlipCaptioningPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`, `use_safetensors=False`, `weights_only=True`). **Executed ≠ hosted artifact:** the notebook runs `pytorch_model.bin` (the only PyTorch weight file upstream; no SafeTensors exists at this revision); the `tf_model.h5` DIMER hosts is never listed or fetched, and both digests are in the card. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `pyarrow`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample's captions are the `id`, `answer`, `question_type` and `text_detected` columns of one object in the Hub dataset repository `mm-eval/VizWiz-Captions` at the immutable revision `c4a6d897836e7885d0095134f92d392e4e770539` (`data/val-00004-of-00005.parquet`, 392,245,504 bytes, SHA-256 `4492465a…`): the declared size and SHA-256 are checked against the pins through the Hub's file metadata before any byte is read, only the parquet footer and those columns are fetched over HTTPS range requests through `pyarrow` (about 0.5 MB), and the decoded columns are refused unless their SHA-256 matches the pin. The 336 photographs of row group 0 are then read from the shard's image column the same way (one range read of about 84 MB), each pinned by size and SHA-256 in the carried `samples.py` and refused on any mismatch; the 318 that carry at least one reference caption are cut **by image** into 208 / 40 / 70 (`check_split_disjoint` asserts no shared image id). The template adds a second *External access* bullet naming the repository, the revision, the file, the byte counts and the CC BY 4.0 licence.
- **Stages (§4.1):** `fetch_annotations` + `fetch_images` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.caption` with sanity checks + `keyword_hits` + `evaluation_report` on the drawn scenes (inference contract) → `constant_caption_baseline` + `colour_neighbour_baseline` + `pipe.evaluate` on the frozen model with the per-category breakdown (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.caption` + `evaluation_report` on the scenes again (inference) → `pipe.save_artifact` → `BlipCaptioningPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the caption is generated text with no score, probability or correctness signal; BLEU-4, ROUGE-L, CIDEr-D and unigram F1 are corpus-level agreement with reference captions (own pure-Python implementations of the `coco-caption` definitions; CIDEr-D's document frequencies come from the evaluated set, so its absolute value is not a leaderboard number); no acceptance threshold ships. The scenes re-captioned after adaptation carry a `not-measurable` verdict because no reference captions are authored for drawings.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the constant-caption (corpus medoid) and colour-nearest-neighbour baselines and the frozen model are scored on the same 70 test photographs as the adapted model, on all four metrics and per category; every metric is labelled as one seeded split of one corpus with no dispersion estimate, and the notebook says explicitly that the frozen model is already a competent captioner, that the measured gain is a few hundredths of CIDEr-D with BLEU-4 moving the other way, and that a higher learning rate overfits and is reported by the selector keeping epoch 0.
- **Split integrity (SPL1–SPL8):** the split is seeded and image-disjoint; validation (40 photographs, noisy) selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that images from few photographers or sessions must be split by source.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `IMAGE_SIZE` (384), `MAX_PREFIX_CHARS` (128), `MAX_NEW_TOKENS` (64), `DEFAULT_MAX_NEW_TOKENS` (30), `DECODING`, the record bounds (8..5,000), `MIN_CAPTIONS` (1), `MAX_CAPTION_CHARS` (500) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (names flattened, no `extractall`) into the runtime and its records flow through the same validation, image-disjoint split, baselines, fine-tuning, evaluation, export and reload cells. The expected schema and the privacy guidance — photographs of people, documents or homes are restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/blip_captioning_train.jsonl` in the JSONL shape.
- Licence: the weights are BSD-3-Clause and the notebook, README, card and `docs/WEIGHTS.md` say so; the corpus is CC BY 4.0 and is not redistributed — the export records its repository, revision, file pin and licence under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
