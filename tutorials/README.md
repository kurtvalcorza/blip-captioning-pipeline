## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/blip_captioning_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 8-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry — the pickle checkpoint included — before `torch` is imported; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True`, `trust_remote_code=False`, `use_safetensors=False` and `weights_only=True` through `BlipForConditionalGeneration`/`BlipProcessor`. **Executed ≠ hosted artifact:** the notebook runs `pytorch_model.bin` (the only PyTorch weight file upstream; no SafeTensors exists at this revision); the `tf_model.h5` DIMER hosts is never listed or fetched, and both digests are in the card. The notebook's only external dependencies are the pinned PyPI distributions and the Hub at the model revision.
- **Role stages:** `validate_inputs` writes `outputs/blip_captioning_input_manifest.json` with the schema (384×384 resize, decoding rule), the ceilings, each input's observed mode and size, the checked prefix, the budget, the verdict, and one recorded rejection finding from the tiny-image probe; `evaluation_report` writes `outputs/blip_captioning_evaluation_report.json` — `not-measurable` on the default path (no reference captions exist; the keyword observations are attached under `observations` and are not a metric), `sample-sanity` with one `unigram_f1` entry per image only when the learner supplies references (stated as bag-of-words overlap, not CIDEr/BLEU/SPICE).
- The default sample is three deterministic cartoon scenes drawn in code with Pillow (no text rendering, so their digests are stable across Pillow builds) — the same drawings the smoke run used; no reference captions are authored because a caption the author writes is not an annotation standard, so the report is `not-measurable` **by design** and the keyword checks (`house`, `tree`, `red`; `beach`, `sail`, `sun`; `apple`, `orange`) are observations the learner can verify by eye. The smoke run's miscount (the orange captioned as a second apple) is recorded in the notebook prose.
- Score semantics (UNC1–UNC4): the caption is generated text with no score, probability or correctness signal; the notebook says so before the first caption and again in the interpretation section, and states that the model captions empty images (blank → a striped rug, noise → a TV screen in the smoke run). The token budget and the prefix are caller-owned request parameters exposed as `# @param` values (defaults `DEFAULT_MAX_NEW_TOKENS = 30`, empty prefix = unconditional) and passed explicitly on every `caption` call; `truncated` is surfaced and explained. The notebook performs no validation of its own — images, prefix and budget are checked only by the pipeline's `validate_inputs`/`caption` path.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `IMAGE_SIZE` (384), `MAX_PREFIX_CHARS` (128), `MAX_NEW_TOKENS` (64), `DEFAULT_MAX_NEW_TOKENS` (30) and `DECODING` are printed before the model runs.
- CPU is documented as adequate (card-measured 3.9 s load, 0.2–0.5 s per caption on the drawn scenes; 0.49 s on a 4096×4096 blank image); the notebook states that cost is per image and that GPU output need not match CPU output token-for-token.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
